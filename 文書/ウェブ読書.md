# ウェブ読書（試験版）

紹介ページの「綴りで読む」にURLを入力すると、ページを縦書きに組み直します。URLの指定は `/?w=https%3A%2F%2Fexample.jp%2F` の形式です。

直接の取得には相手サイトのCORS許可が必要です。取得できない場合は、[ブラウザー拡張機能](拡張機能.md)か保存したHTMLを使用します。読書画面の「綴りで読む」をブックマークバーに追加し、元のサイトで実行する方法もありますが、サイトのCSPやウィンドウの分離設定によって失敗する場合があります。

## 操作

- 「詳しい意味解析」：文章の意味ベクトルを使って領域を分類します。初回はモデルを取得します。
- 「元の配置」：取り込んだページの配置を表示します。
- 「更新」：元のページを取り込み直します。
- 「保存を削除」：表示中のURLと表示寸法に対応する組版結果を削除します。
- 「HTMLを開く」：保存したHTMLを取り込みます。

処理中は元の配置を表示し、完了後に縦書きへ切り替えます。進捗表示には現在の工程、読込量、解析済み領域数、実測速度から求めた残り時間の目安を表示します。

## 解析と組版

処理本体は `src/読取/`、読書画面は `例/読書.ts` にあります。ライブラリーの配布物 `dist/` とは別に構築します。

DOMの階層、HTML要素、ARIA属性、文章、計算済みの書式、領域の寸法と位置を収集します。文章は `Intl.Segmenter` で分割し、元の文字位置を保持します。領域間の包含・順序・整列・ラベル・近接関係を使って分類結果を調整します。

意味解析には `Xenova/paraphrase-multilingual-MiniLM-L12-v2` のリビジョン `2c4055b12046f11709e9df2c122e59ffbdc2f900` を使用します。Transformers.jsでWebGPUとWASMを並行実行し、処理時間に応じて割当て件数を調整します。WebGPUは対応時にFP16、それ以外はFP32、WASMはQ8を使用します。WASMワーカーはCPU数とメモリー量に応じて最大3個です。

本文・見出し・注記の分類から書字方向を決めます。コード・表・操作部は横書きに保ちます。組版後は候補となる高さを実測で比較し、はみ出す領域を横書きに戻します。

## 保存

| 保存先 | 内容 | 上限 |
|---|---|---|
| IndexedDB | 組版済みHTML・元のHTML・解析結果 | 24件・32 MiB |
| Cache API | 文章ごとの意味ベクトル | 2,048件 |
| モデルのブラウザーキャッシュ | モデルとトークナイザー | ブラウザーの保存領域による |

組版の保存キーには処理系の版、モデルのリビジョン、数値精度の方針、URLのクエリー、表示寸法、意味解析の有無を含めます。フラグメントは同じ組版を共有します。「更新」と表示寸法の変更では既存の意味ベクトルを再利用します。ブラウザーが保存領域を消去した場合は再取得・再解析が必要です。

## 現在の制限

- 取得するHTMLは2 MiB、構造の測定は12,000要素までです。意味解析は対象のうち文章量の多い384領域に限り、長文は冒頭・中央・末尾を抜粋します。
- 現在の組版処理は元のCSSを除去し、測定した書体・文字サイズ・色などを設定し直します。元のデザイン、アイコンの寸法、フッターなどの領域を十分に保持できない場合があります。
- 意味モデルは文章の類似度を扱うもので、ウェブページの配置を学習した分類器ではありません。領域の評価値は統計的に較正された確率ではありません。
- 取り込んだページのスクリプト、フォーム、編集機能、埋込みフレームは動作しません。意味解析が失敗した場合は構造解析のみで組版します。
- 画像や書体の完全なオフライン保存には対応していません。

## 動作確認

```sh
bun install
bun run build
bunx playwright install chromium
bun run test:browser
bun run test:extension
```

通常の描画試験は固定の意味ベクトルを使います。拡張機能の試験では、同梱ワーカーによるモデルの取得とWASMでの意味解析も実行します。
